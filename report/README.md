# Report preparation

The report will follow the supplied course structure. It will be written after both implementations and their verification have produced evidence.

Required sections:

- Team details and actual contribution percentages (student-provided).
- Executive summary, 200–300 words.
- 1. Introduction, project scope, vibe approach, SDD approach, timeline.
- 2. Stakeholders, functional and non-functional requirements, technology rationale, API and interface specifications, derivation.
- 3. Vibe process, actual prompts, outcomes, and refinements.
- 4. SDD toolkit, environment, requirement derivation, workflow, and actual prompts.
- 5. Verification strategy, audit findings, executed tests, expected versus actual results, and limitations.
- 6. Git workflow, actual push history, tooling, and authentic team contributions.
- 7. Evidence-based comparison, challenges, lessons, and a proposed reusable SDD workflow with a diagram.

No claim of student participation, human acceptance, performance, coverage, toolkit execution, or GitHub publication may be made without supporting evidence. Personal reflections need the student's own input; AI observations will be labeled as such.
